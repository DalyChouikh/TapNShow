# S1 — Supabase Cron on the Free plan calling Vercel every minute

- **Date:** 2026-10-05
- **Project:** `tapnshow-prod` (`dysqhjvwabqahpctytnw`, eu-central-1, Free plan)
- **Question:** Can Supabase Cron + `pg_net` on the Free plan call a Vercel route every minute? (spec §5, §13)
- **Result:** **PASS** — the dispatcher will be scheduled by Supabase Cron every minute; the GitHub Actions fallback is not needed.

## Setup

- `pg_available_extensions`: `pg_cron` 1.6.4 and `pg_net` 0.20.4 available on Free.
- Job `s1-spike-ping`, schedule `* * * * *`, command `select net.http_get(url := 'https://tapnshow.vercel.app/api/health')` — exercises cron → pg_net → Vercel Function (fra1) → database.
- Ran 08:07–18:35 UTC, then `cron.unschedule('s1-spike-ping')` (0 jobs remain).

## Consequences

- Spec §5/§8 stand as written: Supabase Cron calls `POST /api/internal/dispatch` every minute.
- `net._http_response` keeps only ~6 h of history, so dispatcher monitoring must rely on `outbox_jobs` / `send_log` and Sentry, not on pg_net logs.
- The extensions were enabled imperatively for the spike; the M4 migration must declare them (`create extension if not exists pg_cron; create extension if not exists pg_net;`).
