# S4 — Gmail API send from an unverified app

- **Dates:** started 2026-10-05; token-lifetime check due **2026-10-13**
- **Question:** Can organizers connect Gmail and send via the Gmail API before Google verifies the app? What do consent screens, scope classification, refresh-token lifetime and daily limits look like? (spec §8, §9, §13)
- **Status:** **Day 0 PASS** — final verdict after the day-8 refresh check.

## Setup

- Google Cloud project `tapnshow` (no billing). Gmail API enabled.
- Google Auth Platform → Audience: External, publishing status **Testing**, owner's Gmail as test user.
- Data Access: `https://www.googleapis.com/auth/gmail.send` → listed under **sensitive scopes** (owner report) — consistent with Google's Gmail scope docs.
- OAuth client: Web application, redirect URI `http://127.0.0.1:53682/callback` (a first attempt failed with `redirect_uri_mismatch` until the URI was registered exactly).
- Throwaway scripts (spike branch, not merged): loopback consent with `access_type=offline`, `prompt=consent`; send via `gmail.users.messages.send`.

## Evidence (day 0, 2026-10-05)

- Consent completed; token saved with `refresh_token` present and `scope=https://www.googleapis.com/auth/gmail.send` only.
- Send using only the refresh token: `SENT id=1a10b3397151d983` at 2026-10-05T08:34:52Z; delivered to the inbox ("TapNShow S4 spike").

## Documented limits

- Gmail Help, "Limits for sending & getting mail": a regular Gmail account hits a limit at "more than 500 recipients in a single email and or more than 500 emails sent in a day".
- Gmail API usage limits: `messages.send` costs 100 quota units; 6,000 units per minute per user per project → **≤ 60 sends per minute per organizer**; "a limit of 500 recipients per email message" still applies.
- Spec §8 quota: organizer Gmail **500 emails/day**; dispatcher must throttle to **≤ 60 sends/min per organizer**.

## Remaining

Google's OAuth docs (Using OAuth 2.0 → refresh token expiration): *"A Google Cloud Platform project with an OAuth consent screen configured for an external user type and a publishing status of 'Testing' is issued a refresh token expiring in 7 days, unless the only OAuth scopes requested are a subset of name, email address, and user profile."* `gmail.send` is not such a scope, so **Testing status cannot serve real organizers** (connections would break weekly). Production must run with publishing status **In production** (unverified until M9: "unverified app" screen + 100-new-user cap).
