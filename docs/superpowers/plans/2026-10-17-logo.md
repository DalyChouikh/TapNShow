# TapNShow logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the stand-in icon with the approved calendar mark everywhere the app shows its icon, put the mark on the link preview, and serve the 120 px file for Google Cloud.

**Architecture:** The mark stays one function, `appIconSvg(variant)` (`src/lib/brand/app-icon.ts`), now built from named geometry constants that its tests reason about (the farthest drawn point must stay inside the centre circle of radius 40%). Every PNG, the favicon, `BrandMark` and the link preview keep drawing from it. The link preview gets the mark, Archivo Black from a committed TTF, and a URL versioned by a digest of what it shows.

**Tech Stack:** Next.js 16.3.8 (`next/og` `ImageResponse`, route handlers), React 19.2.8, TypeScript 5, bun 1.3.11, Vitest 5.0.3, Playwright 1.63.0, `node:crypto`.

**Spec:** `docs/superpowers/specs/2026-10-17-logo-design.md` (all of it; §2 has the exact drawing, §3 the variants, §5 the edge cases). Parent spec: `docs/superpowers/specs/2026-10-04-tapnshow-design.md` §7.18, §10 (PWA), §15.

## Global Constraints

- Everything in the Global Constraints of the M0+M1 to M9 plans still applies: bun; no `any`, no `unknown`; no `console.*`; JSDoc on every export; imports at the top; no hardcoded values (colours from `palette` in `src/design/tokens.ts`); no emojis; no technical words for users.
- **One drawing:** the mark exists only in `appIconSvg`. No hand-made PNG or SVG of the logo is committed (spec §6, anti-goals).
- **Colours:** only `palette.light` tokens: `ink`, `surface`, `primary`, `success`. No new tokens.
- **Stable favicon URL:** `/favicon.ico` and the `/icons/*` names stay; only `apple-touch-icon.png` changes variant and `logo-120.png` is added.
- **Layering:** `src/config/*` doesn't import from `src/lib/*` (today it never does); the share-image version lives in `src/lib/seo/`.
- **Process:** one branch + PR per task from `.github/pull_request_template.md`, an issue per task under a `[epic] New logo` issue; TDD (watch each test fail for the right reason); the full chain before each PR: `bunx prettier --write <touched> && bun run format:check && bun run lint && bun run typecheck && bun run test -- --run`, then `TZ=UTC bun run test:e2e` and `bun scripts/check-build-log.ts .e2e-build.log`. Never write a closing keyword for an issue that shouldn't close.
- **Screens:** look at every screenshot yourself, send it to the Owner and ask "Looks right?" before merging (390 light, 320 dark, 1024).

## Review Focus

1. **Satori draws the SVG differently from a browser** (rotation, round joins, the outline union): the PNGs must look like the approved mockup. Pinned in Task 1 Step 7 (look at the built PNGs next to the browser's drawing).
2. **The 16 px favicon is muddy** in a real tab, light or dark. Pinned in Task 1 Step 7 (tab screenshots at 1024 light and dark).
3. **The link preview's font isn't found on Vercel** (a file read at build that the deploy doesn't carry), so the image fails or falls back. Pinned in Task 2 Step 6 (e2e fetches the image from a production build) and Task 3 Step 1 (curl on production).
4. **Already-installed apps and shared links keep the old picture.** Pinned in Task 3 Steps 2–4 (the Owner's devices, re-scrape, URL Inspection), as the design's §5 rows 7, 9 and 10 say.
5. **A later edit moves the drawing outside Android's safe circle** (bigger scale, longer rings, more shadow). Pinned in Task 1 Step 1 (`markRadius` × every variant's scale ≤ 0.4 × 512).

  - `markRadius(): number`: the farthest drawn point from `(256, 256)` at scale 1

- [ ] **Step 1: Write the failing tests in `app-icon.test.ts`** (replace the "icon B" tests)

    expect(markRadius() * scale).toBeLessThanOrEqual(0.4 * 512);

it("tilts the calendar -8° around the centre in every variant", () => {

it("draws only theme colours: mint tile, white page, lilac top, ink", () => {

    const { success, surface, primary, ink } = palette.light;
    expect([...colours].sort()).toEqual([success, surface, primary, ink].sort());

it("rounds only the full icon's canvas; square and maskable are full bleed", () => {
